## 1. Executive summary

- **No critical defect.** The library behaves; what is wrong is mostly that the new
  `Audit` standard promises more than it checks, and that the release tooling can lose or
  mis-publish work.
- **The audit has false negatives.** It never looks at `Command.Parameters` or
  `SubcommandEntries`, and it models only the `-h` pages. A description that passes `Audit`
  still wraps on `help man`, `help flags` and `help topics`. (A-1, A-2, A-3)
- **`tools/bump-version.sh` can destroy uncommitted edits** in `clihelp.go` /
  `example/main.go`, and will commit unrelated uncommitted hunks into a tagged, pushed
  release. An interrupt leaves the tree half-bumped. (P-1, P-2, P-3)
- **The library's own `completion` and `manpage` commands print usage and example lines
  without the app name**, so copying them fails. (U-1)
- **Two terminal-safety bugs in this session's rendering changes:** the usage-group
  sentinel is 2 columns wide under East-Asian width settings, and the orphan-heading trim
  leaves a dangling SGR and a wrong count in colour mode. (R-1, R-2)
- **Documentation lies in a few load-bearing places**: the package comment's example does
  not compile; `AGENTS.md` names files that do not exist; the drift test does not scan the
  files that drifted. (D-1, D-2, D-3)
- **The new tests have teeth on the core claims** (85 mutations applied; 64 killed) but 21
  survive, concentrated in `isHeadingLine`, two of three `writeUsage` call sites, nested
  and shortcut traversal, and `markLibraryOwned` recursion. All 21 are closed by
  test-only additions. (T-1…T-9)
- **Best payoff for risk:** P-1/P-2 (a six-line guard in `bump-version.sh`), then A-1
  (audit two more listings), then R-1 (change one constant).

## 2. Findings — high

### [A-1] `Audit` never checks `Parameters` or `SubcommandEntries`
- **Severity** high · **Confidence** high · **Verified** yes (repro) · bug / audit false negative
- **Location** `audit_layout.go` `auditCommandsLayout`; renderer at `render.go` (`renderCommandParams`, `renderCommandSubcommands`)
- **What's wrong** The renderer draws both with the same one-row column logic, and
  `AGENTS.md` promises `Audit` fails "every offender" in a listing. These two listings are
  skipped.
- **Evidence** `Command{Name:"job", Parameters: []Param{{Name:"file", Description: <100 columns>}}}`:
  `Audit` returns nil; `RenderCommand` at width 80 draws the parameter on two rows.
  Reviewer's sweep: 106–116 mismatches per 300 cases for each listing.
- **Fix** In `auditCommandsLayout` add
  `auditListing(scope+" parameters", cmd.Parameters, cmd.Parameters, opts)` and, for
  `SubcommandEntries`, the same on the entries. `SubcommandEntries` descriptions are drawn
  in full (not `firstSentence`), so do not route them through `commandParams`. Where a
  command has entries, the renderer shows them *instead of* `Subcommands`
  (`subcommandEntries(cmd)`); reuse that choice rather than duplicating it.
- **Effort** S · **Risk** apps with long parameter descriptions start failing `Audit`
  (needs a migration line, see D-5) · **Verification** two new cases in
  `TestAuditAgreesWithTheRenderer`.

### [P-1] `bump-version.sh` destroys uncommitted edits on a failed bump
- **Severity** high · **Confidence** high · **Verified** yes (read) · bug / data loss
- **Location** `tools/bump-version.sh:25-28` (`restore`), no dirty-tree check anywhere
- **What's wrong** `restore()` runs `git checkout -- VERSION example/main.go clihelp.go`
  unconditionally. The script never checks those files were clean when it started.
- **Evidence** Reviewer: appended a line to `clihelp.go`, made `check.sh` fail → "Version
  files restored", the line gone, no stash.
- **Fix** After `cd`, refuse unless `git status --porcelain --untracked-files=no` is empty;
  also require the expected branch and an upstream.
- **Effort** S · **Risk** none (it only refuses more) · **Verification** shell test in a
  temp repo: dirty `clihelp.go`, assert non-zero exit and file unchanged.

### [P-2] A bump commits and tags unrelated uncommitted edits
- **Severity** high · **Confidence** high · **Verified** yes (read) · bug
- **Location** `tools/bump-version.sh:79` (`git add` of whole files)
- **What's wrong** Whole-file `git add` takes every uncommitted hunk in `clihelp.go`,
  `example/main.go` and the generated docs, not just the version line.
- **Evidence** Reviewer: a `// wip` line in `clihelp.go` was committed under
  `chore: bump version to 0.3.50`, tagged and pushed to the bare remote.
- **Fix** Same guard as P-1; also turn `generated_were_clean` from a flag into a hard abort.
- **Effort** S · **Verification** same temp-repo test; assert `git show --stat HEAD` lists
  only version-carrying files.

### [U-1] `completion` and `manpage` print usage and examples without the app name
- **Severity** high · **Confidence** high · **Verified** yes (repro) · interface
- **Location** `completion_command.go` (every `UsageLine`/`Examples`), `man.go:529-545`,
  `buildDefaultUsage` (`render.go`)
- **What's wrong** `UsageLine` and example lines are literals with no app name or mount
  path. Every other command prints `Usage:  podctl build …`.
- **Evidence** `RenderCommand(..., "completion")` prints `Usage:  completion <subcommand>`
  and `completion zsh`; `manpage` prints `manpage > myapp.1`. Mounted at depth 2 the
  mismatch with the page's own heading is worse. `Audit` passes because the *example
  validator* already rewrites mounted paths (`examples.go`); the renderer never did.
- **Fix** Resolve library-owned usage and example lines against the real path at render
  time: in `buildDefaultUsage`, for `cmd.libraryOwned`, prefix `appName + " " + path`;
  apply the same to example lines, reusing the rewrite in `examples.go`. Replace `myapp.1`
  with `appName(a)+".1"`. Simplest for commands with no unusual syntax: drop `UsageLine`
  and let the generated line apply.
- **Effort** S–M · **Risk** low; generated docs change · **Verification** a test mounting
  both commands at depth 0/1/2 asserting every `Usage:` and example line starts with
  `appName + path`, for `-h`, `--help`, `help man` and `-E`.

## 8. Design proposal: one layout plan

The root cause behind A-1, A-2, A-3 and A-6 is that the renderer and the audit each decide
"how wide is this row's text" and can disagree. Give the renderer a small description of each
listing — `listing{scope, rows []Param, extra, margin int}` with `textWidth(termWidth,
maxContent)` — produced by one function per page kind. The renderer writes it; `Audit`
walks the same functions. Then a new page cannot be added without the audit seeing it, and
the agreement test becomes a check on one function instead of a sweep over many. Migration
is mechanical and keeps tests green at each step (see A-6); no function body needs
splitting.

## 9. What I would look at with more time

- The same mutation set against `doc/` and `tree/`.
- A property test that walks every page (`-h`, `--help`, `help flags|man|topics`, `-E`) of
  `podctl` and `mail_cli_fake` at widths 40–120 and asserts that, when `Audit` passes, no
  authored description wraps.
- `Options.MaxContentWidth` above 80, where the audit's assumption of 80 does not hold.
- Colour-on wrapping of hanging indents with OSC 8 links.
- `go-audit` is the authority on nesting depth and branch count: the standards name it as the validator. An independent AST count found depth 5 to 6 in `colorizeExampleLineWithApp`, `extractSegmentTokens` and `glueGroups` where `go-audit` reports none; that is a difference in how a heuristic counts, not an open question about the guidelines, and nothing in this review depends on it.
- `mail_cli_fake` still fails `Audit` for reasons that predate this work (`-1, -2, -3...` is
  not a valid shorthand spec; 18 invalid examples).
